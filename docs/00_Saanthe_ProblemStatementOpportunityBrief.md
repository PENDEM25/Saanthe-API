# Problem Statement / Opportunity Brief
## Saanthe — Phase 1: Discovery

*Prepared by: Product (Claude, acting as PM) | Reviewed by: Manoj (Engineer/Founder) | Status: For Decision*

---

### Problem

The requester (a recent MS in Information Systems graduate) does not yet have practical, hands-on understanding of how modern web/software applications are actually designed, built, and maintained at scale for real users. Existing coursework and self-study have provided conceptual/theoretical exposure — that a system is composed of frontend, backend, database, and API layers — but not the practical skill to design, build, and defend such a system independently, end-to-end, using an industry-standard stack.

### Who Has It

The requester themselves, specifically in the context of transitioning into a **Backend Engineer (Python/FastAPI)** role, with a longer-term goal toward **AI Engineering (RAG systems)**. The gap sits squarely between "graduated with an IS degree" and "employable as a backend engineer" — the practical SDLC and system-building experience a hiring company expects a candidate to be able to speak to in interviews.

### Evidence

- Self-reported: theoretical knowledge of the client → API → backend → database flow exists, but no prior hands-on project has been built solo, from requirements through deployment, using a professional stack (Python/FastAPI/PostgreSQL/SQL/pytest/Git).
- Separately, market research already conducted (22 real job postings analyzed) confirms this exact stack and these exact skills — API design, database modeling, testing, SDLC ownership — are directly and repeatedly required for the target role. This isn't a speculative skill gap; it's one already validated against live market demand.

### Why Now

The requester is currently on OPT (work-authorization clock actively running) and actively job-searching, with backend engineering as Plan A. Interview readiness — the ability to explain and defend real technical decisions — is an explicit, time-boxed goal. Delaying hands-on system-building delays interview readiness directly.

### Rough Business Impact

- **If not pursued:** Requester continues interviewing with conceptual knowledge only, at higher risk of failing technical/system-design interview rounds, or of having a resume with no independently verifiable, defensible project.
- **If pursued:** Requester gains one fully-owned, explainable project spanning the entire stack — directly usable as a resume line, a portfolio piece, and a rehearsed interview narrative (design decisions, trade-offs, and rebuild capability).
- No revenue impact (this is a personal/career capital investment, not a commercial venture) — impact is measured in interview-readiness and skill acquisition, not dollars.

### Build vs. Buy

Numerous similar prototype/marketplace projects already exist publicly (GitHub, tutorials, course projects). **Explicitly rejected as a substitute**, because the value here isn't the *artifact* (a working marketplace app) — it's the *process* of independently making and defending every design decision. Using a pre-built solution would defeat the stated purpose. This is a "build," not "buy," by design.

### Recommendation

**✅ Pursue.**

This is a low-risk, high-alignment investment: it directly targets a validated market skill gap (Plan A: backend/FastAPI), for a requester with existing partial technical background (22 months prior SWE experience) and a clear, time-bound motivation (active job search on OPT). No resourcing conflict exists — this is a solo effort with an already-scoped MVP (see Project Charter).
